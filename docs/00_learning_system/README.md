# 通用学习系统

本目录保存的是一套可以迁移到其他领域的学习方法。定位建图是当前实践对象，但这里的流程不依赖某个专业。

## 先判断你是否需要读本目录

- **只想跟着仓库学习定位建图**：不需要先读本目录，直接进入[学习单元目录](../units/README.md)。
- **想查看作者为什么这样安排课程**：阅读[学习地图](learning_map.md)和[诊断报告](diagnostic_report.md)。
- **想把这套方法用于微观经济学、编程或其他领域**：从[新领域启动流程](new_domain_bootstrap.md)开始。
- **正在维护或创建学习单元**：阅读[两小时单元流程](unit_workflow_2h.md)并使用[学习单元模板](../templates/learning_unit.md)。

普通学习者不需要理解本目录中的每一个文件。单元 `README.md` 会在需要时给出直接链接。

## 最简学习方法

整个方法只分两层：

### 第一层：开始一个新领域时，只做一次全局诊断

1. 定义想练成的能力；
2. 闭卷诊断当前基础；
3. 根据缺口排列学习单元；
4. 以后在阶段复盘时再做全局复诊。

全局诊断用于决定“先学什么”，不是每个知识点都要重复进行的考试。

### 第二层：每个单元采用“先学完整，再统一考核”

每个单元按六步执行：

1. 开始：打开单元主页，复制工作簿；
2. 学习：从头到尾学习 `lesson.md`，中途只记录疑问；
3. 练习：完成工作簿中的推导、案例或操作；
4. 实践：运行实验或完成可观察的领域任务；
5. 考核：最后统一完成闭卷终测和费曼讲解；
6. 归档：保存证据并安排延迟复习。

详细时间和文件对应关系见[两小时单元学习流程](unit_workflow_2h.md)。

## 为什么不再在每个小节后考试

频繁的小测会打断连续理解，尤其不适合第一次接触一个完整概念链时。本仓库现在采用：

- 开始整个领域前做一次全局诊断；
- 单元学习过程中允许提问、看例子和修正理解；
- 单元主要内容学完后，再集中做练习、实验和闭卷终测；
- 延迟一段时间后用新题验证是否真正保持。

这既保留了诊断和主动回忆，也让第一次学习更连续。

## AI 与学习者分别做什么

| 阶段 | AI 的角色 | 学习者必须亲自完成 |
|---|---|---|
| 全局诊断 | 考官，只出题和记录 | 原始回答与推理 |
| 单元学习 | 教练，解释、画图、举例和回答疑问 | 阅读、复述和提出具体问题 |
| 练习与实践 | 评审，指出第一处问题并给排查顺序 | 推导、操作、预测和结果解释 |
| 终测 | 考官，按标准评分 | 闭卷答案和费曼讲解 |
| 复习 | 教练与评审 | 延迟主动回忆和迁移任务 |

AI 生成的笔记、答案和代码只能证明材料存在，不能证明学习者已经掌握。

## 什么算学习证据

一个单元不需要制造大量文件，但至少要留下：

1. 自己完成的关键练习或推导；
2. 一项可以观察结果的实践；
3. 一个条件变化或故障案例；
4. 闭卷终测答案与评分；
5. 真实错误及修正；
6. 五分钟费曼输出；
7. 下一次复习日期。

最方便的保存方式是复制单元的 `workbook.md` 到该单元的 `sessions/` 目录，并在同一个文件中完成记录。

## 状态只有四种

- `未开始`：还没有个人会话记录；
- `学习中`：已经开始，但练习、实践或终测尚未完成；
- `待复习`：首次学习证据齐全并达到当天标准；
- `已掌握`：经过延迟复习、变化条件和综合任务验证。

“读完课程”“程序运行成功”或“当天终测通过”都不能单独标记为 `已掌握`。

## 新领域的最短启动路径

只有在复制这套方法到其他领域时，才执行下面的流程：

1. 阅读[新领域启动流程](new_domain_bootstrap.md)；
2. 填写[领域启动模板](../templates/domain_bootstrap.md)；
3. 完成一次全局诊断；
4. 建立学习地图；
5. 用[学习单元模板](../templates/learning_unit.md)创建第一个单元；
6. 按[两小时单元流程](unit_workflow_2h.md)完成第一次学习；
7. 使用[复习计划](review_schedule.md)做延迟验证。
