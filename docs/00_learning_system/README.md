# 通用学习系统

本目录描述的是一套可迁移到不同领域的学习方法。定位建图是本仓库当前的实践
对象，但这里的流程不依赖某个专业术语、公式或工具。

## 从哪里开始

如果要启动一个新领域，按下面的顺序使用：

1. 阅读[新领域启动流程](new_domain_bootstrap.md)，完成选题、目标、诊断和课程拆分；
2. 复制[领域启动模板](../templates/domain_bootstrap.md)，保存该领域的实际决策；
3. 为第一个单元复制[学习单元模板](../templates/learning_unit.md)；
4. 按[两小时单元闭环](unit_workflow_2h.md)完成第一次学习；
5. 每次学习后复制[单次学习记录模板](../templates/session_log.md)保存证据；
6. 使用[复习计划](review_schedule.md)安排主动回忆，并在阶段末重新诊断。

两小时只是本仓库第一轮的默认时间盒，不是所有领域、所有学习者都必须遵守的
课程长度。难度较高的单元可以拆分，已有基础的单元也可以缩短，但不能删除诊断、
实践、复盘和延迟验证。

## 一条证据链

整个系统围绕下面的关系运行：

> 能力目标 → 诊断题 → 能力缺口 → 课程单元 → 学习证据 → 复习记录 → 复诊题

每一项能力目标都应能追溯到诊断题、学习单元和验收证据。反过来，每个单元也
必须说明自己服务于哪项能力，避免课程不断增加却无法解释为什么要学。

常见证据包括：

- 闭卷解释和推理过程；
- 手算、推导、案例判断或实际操作；
- 代码、实验、作品、决策备忘录或口头讲解；
- 条件变化后的迁移表现；
- 故意注入错误后的诊断过程；
- 间隔一段时间后的再次完成结果。

不同领域可以采用不同证据形式。技术学习不应只有阅读笔记，非技术学习也不必
为了形式统一而强行创建代码和自动测试。

## AI 与学习者的边界

AI 可以依次承担考官、教练和评审三种角色，但同一阶段不能混用角色。

- **诊断阶段**：AI 只出题、追问和记录，不提示答案，不在答题中途展开教学。
- **学习阶段**：AI 根据已经暴露的缺口解释、举例和设计练习，不无限扩展范围。
- **评审阶段**：AI 按事先定义的标准检查证据，指出缺口，但不能替学习者声称
  “已经掌握”。
- **学习者**：保留原始回答，亲自完成关键推理与实践，对最终判断和公开内容负责。

AI 生成的参考答案、预置代码和已通过测试只能证明材料可用，不能证明学习者已
经完成相应能力训练。

## “通过”与“掌握”

单元当天达到验收标准，只能记为“本次通过”。“已掌握”至少还需要：

1. 不看答案完成一次主动回忆；
2. 在变化条件下完成迁移任务；
3. 经过间隔复习后仍达到阈值；
4. 在复诊或后续综合任务中没有重复同一根因错误。

因此，[学习进度](progress.md)中的状态必须由实际证据支持，不能因为阅读完文档、
运行预置程序或看到测试通过就直接标记为“已掌握”。

## 通用层与领域层

通用学习系统只保存流程、模板、状态和评价规则。具体领域的概念、题目、资料和
实践任务放在对应单元、证据和参考资料目录中。

本仓库采用以下边界：

- `docs/00_learning_system/`：通用规则和本次学习的总体状态；
- `docs/units/`：定位建图各单元的具体学习内容；
- `experiments/`、`src/`、`tests/`：确有需要时使用的技术实践证据；
- `references/`：教材、论文、术语和公开资源；
- `articles/`：可以独立阅读的阶段复盘，不作为唯一学习记录。

要迁移到新领域，应复制通用流程和模板，再填写该领域内容；不要把定位建图专属
术语替换几个名称后直接当作新课程。
