坐标变换
只是换一把尺子

物理世界没有被搬走。我们只是换了原点、换了坐标轴，再重新读一次数字。

Ap = ARB · Bp + AtB
01 · 核心直觉

点没动，数字变了

坐标不是物体。坐标是“用哪把尺子量出来的读数”。

A 的尺子 5
同一个点 P
B 的尺子 2
只记住：坐标变了，不代表点移动了。
02 · 点和箭头

点怕平移，箭头不怕

点要问“离原点多远”。方向向量只问“朝哪、走多长”。

点：p′ = R·p + t 方向：v′ = R·v
点的齐次末位 = 1 方向的齐次末位 = 0
两个端点一起平移，做差后平移会抵消。
03 · 公式从哪里来

先走到 B，再走到 P

公式不是魔法，只是三段箭头首尾相接。

OₐP = OₐOᵦ + OᵦP Ap = ARB·Bp + AtB
能相加的前提：两个向量都用 A 坐标系表达。
04 · 旋转矩阵

矩阵的列，就是两根轴

第一列画出 xᵦ；第二列画出 yᵦ。都用 A 的眼睛看。

45°
R = [[0.71, -0.71], [0.71, 0.71]]
RᵀR = I det(R) = 1 R⁻¹ = Rᵀ
旋转不改变长度、夹角和形状。
05 · 齐次坐标

最后一位，是“平移开关”

末位为 1：平移生效。末位为 0：平移被关掉。

[ R t ; 0 1 ] · [ p ; 1 ]
点会同时受到旋转和平移。

06 · 变换链

最靠近点的矩阵，先工作

每一段的输出坐标系，必须正好成为下一段的输入坐标系。

mapp = mapTodom · odomTbase · baseTlidar · lidarp
从右向左执行：lidar → base → odom → map。
07 · 逆与相对位姿

回去，不只是把 t 变负

先把方向倒过来，再用新的坐标轴读那段平移。

T⁻¹ = [ Rᵀ −Rᵀt ; 0 1 ] ATB = (WTA)⁻¹ · WTB
自检：T·T⁻¹ ≈ I；点正向再反向应回到原处。
map城市地图：全局一致，可以修正
odom平滑记事本：连续，但会慢慢漂
base车身：机器人现在朝哪、在哪
sensor眼睛和耳朵：原始观测从这里出生
08 · 定位系统

四层坐标系，各做一件事

局部控制要平滑，全局地图要正确。两件事不要塞进同一层。

mapTbase = mapTodom · odomTbase
回环 / GNSS / 重定位：改 map↔odom 局部里程计：保持 odom↔base 连续
TF 树画父→子；点的计算路径从源→目标，方向看起来会相反。
09 · 时间

用拍照时刻，不用打开照片时刻

矩阵方向全对，时间错了，点云一样会偏。

0.10 s
10 m/s
最小平移误差 ≈ v·Δt = 1.00 m
动态 TF 查询测量产生时刻；静态外参才不随时间变。
10 · 工程检查

算得出来，不代表算得对

4×4 矩阵顺序写反，程序通常照样给你一个“看起来很像坐标”的数字。

先写原点、轴向、手性、单位
给每个量标注当前坐标系
用源坐标系原点检查平移
用单位轴检查旋转方向
检查 RᵀR≈I 且 det(R)≈1
检查 T·T⁻¹≈I
逐段结果 = 复合结果
最后核对单位、角度制、时间戳
最终口令：源是谁？目标是谁？现在是什么时刻？
复杂点云出错时，先退回原点、单位轴和可手算的二维例子。

坐标是读数，不是物体。R 统一方向，t 补原点差。矩阵链从最靠近点的一项开始。
