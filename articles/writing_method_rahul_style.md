# 参考 Rahul 文章的写作方法：诊断复盘文章重写指南

> 本文只分析写作方法，作为后续重写 [`00_diagnostic_review.md`](00_diagnostic_review.md) 的依据。本轮不修改原文章；等这套方法审核通过后，再开始重写和配图。

参考文章：Rahul，[*How To Learn Anything 10x Faster Using Claude*](https://x.com/sairahul1/article/2068250224532050089)。

## 一、先说结论

Rahul 的文章不是一篇传统的长教程，而是一个“极短解释 + 可立即使用的工具包”。它先让读者快速认出自己的问题，再用六个结构一致的模块交付可复制提示词，最后把这些模块串成完整系统。

上述两点判断都成立：

1. 当前文章中的 Mermaid、密集表格和长公式不适合知乎、X 等平台的手机阅读，应该更多使用统一风格的章节图片；
2. 当前内容过多，需要明显压缩，让读者能够顺畅读完。

但需要增加两项限制：

- **不能把表格直接截图成图片。** 那只会把横向滚动变成缩小后看不清。图片应该只表达一个核心结论或关系。
- **不能为了缩短而删掉真实证据。** 完整评分、推导、学习计划和实验可以移到仓库，文章仍要保留最有转折意义的原始错误和诊断结果。

一句话概括后续重写原则：

> 参考 Rahul 的轻入口、快节奏和强交付，但用我自己的真实诊断、错误与仓库证据建立可信度。

## 二、分析范围与事实边界

从现有中文翻译稿统计，Rahul 的文章约有 4,959 个字符，其中很大一部分是六段可复制提示词；真正承担叙述的文字很短。全文有九张主要图片：一张封面，以及“随手提问”、六种方法和“如何串起来”各一张。

重写前的诊断复盘文章约有 11,966 个字符，包含十二个二级标题、五张表、十四组独立公式和一张 Mermaid 图。它记录得更完整，但阅读负担也明显更高。这里的统计以提交 [`a130761`](https://github.com/XiaoJiNu/localization-mapping-learning/commit/a1307618d3eeef747fc6b819f5bf033d2ecdc662) 为基准，正文更新后不再作为最新数据。

这组数字只用于比较阅读结构。由于公开页面无法可靠提供完整互动数据，本文不会虚构点赞、转发或收藏数量。下面的“为什么受欢迎”是根据文章结构、可复制性和跨平台阅读特点做出的传播机制分析，不是已经被统计数据证明的因果结论。

## 三、Rahul 怎样组织整篇文章

### 1. 标题一次交代收益、幅度和工具

标题采用了很清楚的公式：

> 如何获得一个普遍想要的结果 + 明显的速度承诺 + 使用一个热门工具

“学会任何东西”扩大了受众，“10x Faster”制造点击动力，“Using Claude”告诉读者实现手段。它传播性很强，但“十倍”并没有在文中通过实验数据证明。因此，我们可以借鉴标题的清晰度，不能把传播性表达写成已验证事实。

现有标题“我用 ChatGPT 实践‘十倍学习法’学习定位建图：第一次诊断复盘”可以保留。它同时包含方法、工具、应用领域和真实阶段，比笼统承诺更可信。

### 2. 开头先让读者认出自己

Rahul 没有先解释学习理论，而是从一个普遍经历开始：AI 可以快速回答任何问题，人却容易随手提问、短暂感觉理解，几天后又什么都说不出来。

这个开头采用了“熟悉场景—反常结果—指出原因—给出方案”的顺序：

1. 学习好像变容易了；
2. 实际上又变得更混乱；
3. 问题不只是 AI，而是使用方式；
4. 接下来给出六个可以立即使用的提示词。

每一小段只表达一个意思，读者在很短时间内就能知道“这篇文章在说我的问题”。

诊断复盘更适合用一次真实错误开场。例如：我写对了坐标变换链，却解释不清为什么左乘；紧接着又把齐次变换的逆误写成了转置。这样可以先让读者看到冲突，再补充个人背景和方法来源。

### 3. 先给一张简单地图，再讲六个模块

Rahul 先把真正的学习压缩为四种需要：路径、测试、压缩和反馈循环。读者先得到一个简单心智模型，后面看到六个提示词时，就知道每一部分在解决什么问题。

现有诊断复盘在前半部分同时出现六类方法、五种能力、九个模块、五级阶梯和十个学习单元。它们各自都正确，但第一次阅读时层级过多。

重写后，前半部分只需要先交代我实际执行的四步：

1. 定义可验证能力；
2. 进行闭卷诊断；
3. 根据错误形成能力画像和计划；
4. 用仓库保存推导、测验、实验和复习证据。

五级阶梯、核心资源和二十小时计划，应在诊断结果出现以后再介绍。

### 4. 六个模块使用同一模板

Rahul 的六个部分几乎采用同一种结构：

1. 一个带动作和收益的标题；
2. 一句说明它解决什么问题；
3. 一张章节图片；
4. 一到三段短解释；
5. 一段可以直接复制的提示词。

重复的结构降低了阅读成本。读者读完第一节，就知道后面应该怎么读；只扫标题也能了解全文，深入阅读时又能拿走现成工具。

我们的三个代表性诊断案例也应统一为：

1. ChatGPT 问了什么；
2. 我当时怎样回答；
3. 真正的错误在哪里；
4. 这个错误怎样改变了后续学习安排。

### 5. 最后重新把零件串成系统

六个提示词讲完以后，Rahul 没有直接结束，而是重新说明它们的使用顺序，并再次压缩为“路径—测试—压缩—重复”。这让读者记住的不是六段孤立提示词，而是一套完整方法。

文章结尾的收藏、转发和立即替换主题等行动号召，也与文章的工具属性一致。读者确实可能在以后反复使用这些提示词，所以收藏不是额外请求，而是正文用途的自然延伸。

## 四、它使用了哪些具体写作技巧

### 1. 一段只承担一个观点

原文大量使用一到三句话的短段落，并通过留白和分隔线控制节奏。读者可以随时暂停，也可以快速找到下一节。

后续文章不需要机械限制每段字数，但应避免一个段落同时解释背景、公式、错误、意义和下一步。核心判断可以独立成段。

### 2. 多用对比，不堆抽象理论

原文不断使用容易理解的对照：得到答案与真正学会、被动阅读与主动回忆、收集资源与使用资源、噪音与信号。

诊断复盘也有一个天然对照：

> 以前，我先让 AI 解释；这一次，我先让 AI 考我。

这句话应该成为全文主线，而不是埋在方法说明中。

### 3. 用具体数字降低抽象感

六个提示词、五个等级、二十小时、十个单元、五个资源、五分钟速查，这些数字让方法看起来可以执行，也便于读者记忆和复述。

诊断过程中的数字更多，因此要主动做减法。正文只突出三个关键数字即可：九个模块用于诊断，五级阶梯表示能力深度，十个两小时单元构成第一轮学习。完整评分和单元明细放在仓库链接中。

### 4. 交付可以马上使用的东西

Rahul 不只解释学习方法，还给出六段可复制提示词。读者即使没有看完全文，也能带走其中一个工具。这直接增加了文章的保存价值。

重写后仍应保留一个精简的定位建图诊断提示词，并把完整版链接到仓库。否则文章容易只剩个人复盘，读者读完却不知道怎样开始。

### 5. 先写结果，再解释原理

每个章节标题和副标题都会先告诉读者“这部分能得到什么”，随后才解释为什么有效。它尊重了社交平台读者先判断价值、再决定是否投入时间的阅读方式。

后续标题也应从目录型改为结论或冲突型，例如：

- 我没有先让 ChatGPT 教我；
- 第一道题就暴露了“会写不会解释”；
- 九个模块后，我得到了一张不均匀的能力画像；
- 诊断不能停在聊天框里；
- 接下来的二十小时只补最关键的短板。

## 五、为什么这种文章容易受欢迎

以下是根据写作结构做出的合理推断。

### 1. 它命中了一个普遍而及时的问题

很多人已经使用 AI 学习，却无法判断自己是真的掌握，还是只是在阅读一份流畅答案。这个问题不受专业限制，几乎所有 AI 用户都能代入。

### 2. 标题的预期收益很高

“学任何东西”“十倍速度”和“Claude”同时提供了广泛需求、强收益和当下工具热度。读者只看标题，就能理解阅读可能带来的回报。

### 3. 使用门槛很低

读者不需要先理解学习科学，只要复制提示词并替换主题，就可以在当天开始尝试。高价值感与低启动成本同时存在。

### 4. 文章天然值得保存和转发

六个提示词分别适用于规划、考试、复习、找资源和费曼讲解，不会在一次阅读后失效。文章更像一个以后还会调用的工具箱，而不是读完即结束的观点文章。

### 5. 非常适合手机扫读

编号标题、短段落、固定模板和章节图片，让读者不必严格从头读到尾。每个模块都能独立理解，也适合截取和分享。

### 6. 它给读者明确的身份想象

“私人教师、考官、资源策展人和学习伙伴”比“用大模型辅助学习”具体得多。读者很容易想象 AI 承担这些角色后，自己的学习方式会发生什么变化。

### 7. 读完以后有明确下一步

文章最后没有停在概念总结，而是要求读者选择主题、替换变量并开始运行。它缩短了“觉得有道理”到“真正采取行动”的距离。

需要注意：这些特点可能提高可读性、收藏价值和传播性，却不能证明“十倍提速”本身成立。

## 六、Rahul 的图片是怎样工作的

### 1. 图片承担章节标题卡，而不是装饰

原文封面紧跟标题，先交付整套学习系统的视觉预告；其余八张图基本都放在章节标题之后、解释文字之前。读者先用两三秒理解本节中心，再阅读文字和提示词。

九张图分别承担九个认知任务：全文总览、随手提问的问题、五级阶梯、二十小时计划、逐级考试、一页速查、资源筛选、费曼循环和完整学习系统。

### 2. 每张图只表达一个中心命题

图片使用台阶、漏斗、对照、循环和步骤链等直观隐喻，而不是复杂系统图。一张图通常只有一个短标题、一个主要视觉关系和少量标签。即使脱离正文，也能作为一张可收藏的知识卡。

### 3. 风格统一，但构图不机械重复

原图整体接近白纸手绘信息图：黑色轮廓配少量蓝、橙、绿、红点色，使用箭头、旗帜、台阶和循环等简单元素。统一的字体、颜色和线条形成系列感，不同的视觉隐喻又避免了九张图完全一样。

借鉴时应学习这种信息组织方式，不复制原图的具体构图、字形或图标。

### 4. 适合本文章的图片规范

建议最终使用六到八张图，理想数量为七张：一张封面和六张正文图。文章压缩到 6,000—8,000 个字符后，平均每个关键转折安排一张，不为凑数量强行配图。

下面是首版制作约束，不是知乎或 X 的官方标准。成图后仍需分别在两个平台的手机端预览，再调整比例、字号和裁切安全区。

图片建议遵守以下规则：

- 封面使用约 2.5:1 的横幅比例；正文图统一使用 16:9；
- 使用 PNG，避免文字经过 JPEG 压缩后模糊；
- 四周至少保留 7%—8% 安全区，重要信息放在中央区域；
- 每张图最多五到六个主要节点；
- 每个标签尽量控制在二到六个汉字，全图正文不超过约五十个汉字；
- 黑色或深灰为主，固定少量强调色；
- 不把完整公式、文件路径、九行评分或十个学习单元塞入图片；
- 正文必须在没有图片时仍能独立读懂。

### 5. 配图优先级

首轮先完成四张必需图：

1. **封面：** 我先让 ChatGPT 考我，而不是教我；
2. **实际使用路径：** 目标—诊断—画像—计划—仓库证据；
3. **三个“以为会了”：** 坐标变换、概率融合和 IMU；
4. **真实能力画像：** 系统关系较强，数学与传感器基础较弱。

文章仍然偏长或某个转折仅靠文字不易理解时，再增加三张可选图：随手问答与结构化学习对照、第二轮学习闭环、二十小时三阶段路线。

如果需要更突出“聊天怎样变成仓库”，可以把第七张拆成“仓库证据”和“二十小时路线”两张，总数增加到八张。

## 七、当前文章最需要解决的问题

当前稿更像一份完整报告：同时介绍原方法、记录诊断、讲解定位建图知识、展示能力画像、索引仓库并提供提示词。重写时重点解决四个问题：

- **核心冲突出现太晚。** 首屏应先呈现一个真实错误，再补充个人背景和方法来源。
- **诊断案例和推导过多。** 五个案例只完整保留三个：

1. 会连接坐标链，却把刚体变换的逆当成转置；
2. 会计算权重，却混淆随机变量相加与贝叶斯融合；
3. 做过多传感器工程，却把 IMU 的估计结果当成直接测量。

- **方法说明重复。** 原方法、第二轮改造、二十小时路线和他人复用合并为一条叙事。
- **独有价值不够突出。** Rahul 提供通用提示词，本次实践还有原始回答、意外错误、能力画像、代码实验、自动测试和复习计划。应压缩推导，保留错误怎样改变判断、结论怎样得到验证。

最终采用两层结构：文章讲清故事、方法、关键发现和结果；仓库保存完整诊断、推导、评分、计划和实验代码。

## 八、建议的重写结构与篇幅

后续正文建议控制在约 6,000—7,500 个字符。这个数字是编辑目标，不是机械上限；技术内容需要讲清，但不再追求把仓库信息全部塞进文章。

### 1. 开头钩子：200—300 字符

用一个真实错误开场，三段内交代冲突、使用方式的改变，以及本文会给读者什么。

### 2. 为什么改变 AI 学习方式：400—600 字符

只保留“看懂不等于会用”的核心。作者背景只写与这个反差有关的部分。

### 3. 我怎样实际执行诊断：700—900 字符

说明五种能力、三个角色、九个模块、闭卷回答、一次一题和只纠正错误部分。

### 4. 三个关键诊断瞬间：1,800—2,400 字符

每个案例使用“问题—原回答—漏洞—意义”的统一结构，不展开完整课堂推导。

### 5. 诊断后的能力画像：400—600 字符

用“已有优势”和“优先补齐”两组短列表代替九行评分表。

### 6. 对话怎样变成计划和仓库：600—800 字符

只说明诊断报告、学习地图、核心资源、实验与测试三类证据，具体目录用少量链接承接。

### 7. 方法失控与第二轮改造：500—700 字符

讲清 IMU 追问失控、问题上限、AI 评分边界和事实核验。

### 8. 可复制方法与提示词：600—900 字符

正文放精简版本，完整版放仓库。读者应能在文章结束前立即开始一次诊断。

### 9. 结尾：200—300 字符

说明当前只完成第一次诊断，后面会用延迟测试、错误复发率、实验和项目迁移验证效果。

## 九、哪些内容应该移到仓库

下列内容不应删除，只是不再全部放进社交文章正文：

- 九个模块的完整评分和遗漏项；
- 最小二乘与概率融合的完整推导；
- 十个学习单元的逐项任务；
- 五级阶梯的全部过关标准；
- 完整资源说明和公开项目索引；
- 完整版基础诊断提示词；
- 代码、调试记录、测试和延迟复习结果。

正文只保留三个到五个最重要的仓库入口。链接是证据出口，不应打断每一段叙事。

## 十、不能照搬 Rahul 的地方

- **不照搬未经证明的承诺。** “十倍”是被实践的方法名称，本轮尚未证明真的提速十倍。
- **不把提示词当成事实来源。** 定位建图的坐标、时间、单位和算法边界仍需教材、官方文档、代码与实验交叉验证。
- **不为缩短而牺牲真实过程。** 原始错误、追问失控和学习顺序改变正是本次实践的价值。
- **不过度模仿营销语气。** 可以使用明确标题、短句和行动号召，但不需要大量感叹号、夸张判断或强迫转发。

## 十一、重写前后的检查清单

重写完成后，应逐项检查：

- [ ] 前三段是否已经出现具体错误、意外发现和阅读承诺？
- [ ] 不看仓库，读者能否复述我是怎样使用这套方法的？
- [ ] 是否只完整保留三个最有转折意义的案例？
- [ ] 每个案例是否都包含原回答、真正漏洞和后续影响？
- [ ] 学习阶梯、核心资源和二十小时第一轮是否都有体现但不过度展开？

## 十二、最终写作原则

> 先用真实错误吸引读者，再讲我是怎样诊断的；先给关键结论，再把完整证据交给仓库；每一节只解决一个问题，并让读者带走一个可以立即执行的动作。
